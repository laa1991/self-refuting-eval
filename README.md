# 一套能「自己砍自己」的评测流程

> 用偏好对（preference pairs）做后训练时，**怎么知道模型真的变了** —— 而不仅仅是「跑通了」。
>
> 这不是一个模型，也不是一个数据集。它是一套**流程**：把「A 比 B 更接近人类判断」这个模糊的问题，
> 变成一组**带区间、带对照、能被自己推翻**的读数。

---

## 为什么需要它（四个会骗人的地方）

| 你会遇到的 | 症状 | 这里的对策 |
|---|---|---|
| 差别是噪声还是信号？ | n=57 的均值差 0.2，没有区间 | **配对差值 + CI95 + 符号检验**（`paired_stats.py`） |
| 是不是「更长的就更好」？ | 两臂长度差 2 倍 | 造表前先做 **cue 检查**（长度 / 小标题 / 空话词 / 英文括注），并写进任务书：**长度与版式不计分** |
| 「更像人类」是不是只在模仿口气？ | 判读者说「写得像」 | **换镜头**（内容镜 vs 写法镜）+ **正负对照** |
| **我自己的解释对不对？** | 我有故事、数据支持它 | **预注册**（判据先写死）+ **中性对照**（见下） |

**最贵的是最后一行** —— 前三个是技术问题，最后一个是「我怎么知道自己没在自欺」。

---

## 四个装置

| 文件 | 它回答什么 |
|---|---|
| `tools/mk_blind_sheet.mjs` | 造一张**盲表**：把两臂输出按种子随机分到 A / B（**同一个种子 + 同一批数据 ⇒ 同一张表**，可复算），判读者看不出谁是谁；同时产出 `key.json`（**判读者不许读它**） |
| `tools/judge_brief.template.md` | 盲评**任务书模板**（每张表生成一份）：三条判据 · 「两侧独立打分」· 「同分即打平，不许硬拆」· 「长度与版式不计分」· 硬边界 |
| `tools/paired_stats.py` | 算**配对差值**：`d̄` / `sd` / `SE` / `CI95` / 符号检验 + 每一侧的**绝对档分布**（← 一侧饱和时只读 `d̄` 会误判，所以档分布和它一起报） |
| `tools/probe_logp.py` | **教师强制**：不看模型生成什么，只量它给一条**现成答案**多大概率 —— 0 训练、几秒钟、每行方向一致 |

## 一条命令（先跑 toy）

```bash
# ① 配对统计（不需要模型，秒级；toy 是合成数据，六条）
python tools/paired_stats.py --a toy/blind_a.jsonl --b toy/blind_b.jsonl \
    --key score --label-a SFT --label-b DPO

# ② 教师强制：量「模型给这条现成答案多大概率」（需要一张卡）
python tools/probe_logp.py --model Qwen/Qwen2.5-1.5B-Instruct \
    --data toy/pairs.jsonl --field chosen --out toy/logp_base.jsonl
```

**预期输出**（① 的真实输出，逐字；数字随数据变）：

```
=== 配对差值（SFT - DPO）===
字段 = score | 按 id 配对 | n = 6
d̄ = +0.6667 | sd = 0.5164 | SE = 0.2108
CI95 = [+0.2535, +1.0799]   ← 不含 0
符号：d>0 4 行 · d=0 2 行 · d<0 0 行 | 二项精确双侧 p = 0.1250
每一侧的绝对档分布：SFT {1:3, 2:3} · DPO {0:1, 1:5}
  ⚠️ 若某一侧大量落在顶档或底档，d̄ 会被压住（饱和）—— 这时要读档分布，不要只读 d̄
```

⚠️ **toy 这份输出本身就带一个教训**：**CI 不含 0，而符号检验 p = 0.125** —— 六条样本太小，两个判据要一起看，**别挑好看的那个报**。

**空结果会分三种情况说话**（「没有数据」其实有三种不同的事）：

```
[!] 配对后不足两条 —— 分三种情况查：
    A: 读入 6 行，其中 6 行缺 `id` 或 `nope`
    ⇒ 读入 0 行 = 路径不对；读入 >0 但全缺字段 = 字段名不对；都有但配不上 = id 不是同一套
```

---

## 这个方法最要紧的一条：**对照要配平，而且你会先失败两次**

真实经历（这就是这套流程被写出来的原因）：

1. 我先做了一个**中性对照**（把一段与研究无关的文字喂给同样的臂），发现 DPO 在它上面也降 ⇒ **砍掉自己的一句读法** ✅
2. 然后我发现 **那个对照本身有洞**：中性文本是在**「情境留空」**的 prompt 下打分的，而人类答案是在**真情境**下打的 ⇒ **两次测量连上下文都不一样** ⇒ 重做**配对版**（同一批情境，只换目标文本）✅
3. **配对版仍有一样没配平：长度**（40 字 vs 210 字）⇒ 于是 —— **不下结论，把那层标成「未量」。**

> **判据**：**你为一句结论做的每一个对照，都要问它「除了你想动的那样东西，还动了什么」。**
> 配不平就别读 —— **「未量」是一个合法的结论**，比一个漂亮的错结论值钱。

---

## 这套流程**不**证明什么

- 它量的是「**更像人类写的那一条**」，**是代理，不是判断能力本身**。
- 教师强制量的是「**给它看，它认不认**」—— **认 ≠ 写得出**（表示层 ≠ 生成层）。
- n 都是几十量级；**小于约 0.2 的差在这把尺上分辨率不足**（这个门槛是先量过的，不是拍的）。

## 这套包自己验过（不是「应该能跑」）

| 装置 | 正例 | 负对照 |
|---|---|---|
| `mk_blind_sheet.mjs` | 6 块表 + key 出齐；**同种子重跑 ⇒ key 的 sha256 逐字相同** | **换种子 ⇒ key 不同**（证明种子真的在起作用） |
| `paired_stats.py` | 出 `d̄` / CI / 符号 / 档分布，`EXIT=0` | 三条各自的空结果都有说法：**路径错** / **字段名错** / **id 不是同一套**，各 `EXIT=1` |
| `probe_logp.py` | `--help` 参数层通 | 字段名写错 ⇒ `[!] 一条都没算出来` + `EXIT=1` |

**这个包把自己写出来的过程也留在了这里** —— 上面三条负对照里有两条，是我在开发时真踩出来的：

1. **Windows 下脚本直接被中文打崩**：Python 的 stdout 默认 GBK，而脚本里有 `−`（数学减号）与 `❗` ⇒ `UnicodeEncodeError`。**换一台机器就复现。** 修法：开头给 stdout 钉 UTF-8，且少用异体符号。
2. **key 里写的是占位符而不是真臂名** ⇒ 下游分析器没法用。**这个错只有把整个链路跑通一次才会露出来。**

> **一个工具在它自己没被检验之前，不能替结论说话。** —— 所以这一节比上面那些说明都重要。
